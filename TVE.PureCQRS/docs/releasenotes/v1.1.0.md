# Release `v1.1.0`

## Tổng quan

Phiên bản `1.1.0` mở rộng `TVE.PureCQRS` với các tính năng nâng cao thường thấy trong các thư viện
mediator, được triển khai theo hướng tối ưu: **hỗ trợ hủy xuyên pipeline**, **dispatch notification
đa hình (covariant)**, và **xử lý ngoại lệ khai báo** — đồng thời hợp nhất đường xử lý cho command
void để không còn "lọt" pipeline.

Vẫn hỗ trợ `net7.0`, `net8.0`, `net9.0`. Giữ giấy phép MIT.

## Tính năng mới

### 1. `CancellationToken` trong pipeline delegate

`RequestHandlerDelegate<TResponse>` nay nhận một `CancellationToken`:

```csharp
public delegate Task<TResponse> RequestHandlerDelegate<TResponse>(CancellationToken cancellationToken = default);
```

Behavior nên chuyển tiếp token xuống bước kế tiếp:

```csharp
var response = await next(cancellationToken);
```

> **Tương thích ngược:** tham số có giá trị mặc định, nên behavior cũ gọi `next()` vẫn biên dịch
> và chạy bình thường.

### 2. Covariant (polymorphic) notification dispatch

Khi `Publish` một notification, nó được giao tới handler đăng ký cho:

- chính type cụ thể của nó,
- các lớp cha (base class) là `INotification`,
- các interface notification mà nó kế thừa (kể cả `INotification`).

```csharp
public abstract record DomainEvent : INotification;
public sealed record OrderPlaced(int OrderId) : DomainEvent;

public sealed class DomainEventAuditor : INotificationHandler<DomainEvent> { /* ... */ }

await publisher.Publish(new OrderPlaced(1)); // DomainEventAuditor được gọi
```

- Bản đồ `type → invoker` được **cache một lần cho mỗi type notification**.
- Handler đăng ký cho cả cha lẫn con chỉ chạy **một lần** (dedupe theo instance).
- Không phụ thuộc khả năng hỗ trợ variance của DI container.

### 3. Exception handlers & actions

Hai abstraction mới cho xử lý lỗi khai báo:

- `IRequestExceptionHandler<TRequest, TResponse, TException>`: **phục hồi** lỗi bằng
  `state.SetHandled(response)`. Được thử theo thứ tự type exception cụ thể nhất trước; handler đầu tiên
  đánh dấu handled sẽ thắng và giá trị của nó được trả về thay cho việc ném lỗi.
- `IRequestExceptionAction<TRequest, TException>`: **side-effect** (log, metrics, bù trừ...) khi có
  lỗi; sau khi chạy xong tất cả action khớp, exception vẫn được ném lại.

```csharp
public sealed class GetPriceExceptionHandler
    : IRequestExceptionHandler<GetPriceQuery, decimal, HttpRequestException>
{
    public Task Handle(GetPriceQuery request, HttpRequestException ex,
        RequestExceptionHandlerState<decimal> state, CancellationToken ct)
    {
        state.SetHandled(0m);
        return Task.CompletedTask;
    }
}
```

Không cần cấu hình thêm — chỉ cần khai báo handler/action trong assembly đã đăng ký.

### 4. Command void đi qua pipeline đầy đủ

`IRequest` (command không response) nay được mô hình hóa là `IRequest<Unit>`. Nhờ đó command void
chạy qua **cùng một đường pipeline** với request có response: behaviors, và exception handling đều áp
dụng. Kiểu `Unit` mới biểu diễn "không có giá trị".

> Trước v1.1.0, command void bỏ qua toàn bộ pipeline behavior.

### 5. Constrained open-generic request handlers

Handler generic được **đóng (close) lúc runtime** cho đúng cặp request/response cụ thể — kể cả khi
số tham số generic của handler *khác* với số tham số của interface đã đóng (điều container DI không
làm được):

```csharp
public sealed record WrapQuery<T>(T Input) : IRequest<Box<T>>;

// 1 tham số generic (T), nhưng interface đóng là IRequestHandler<WrapQuery<T>, Box<T>>
public sealed class WrapHandler<T> : IRequestHandler<WrapQuery<T>, Box<T>>
{
    public Task<Box<T>> Handle(WrapQuery<T> request, CancellationToken ct)
        => Task.FromResult(new Box<T> { Value = request.Input });
}

var box = await sender.Send(new WrapQuery<int>(7)); // WrapHandler<int> được đóng & gọi
```

- Ràng buộc generic (`where T : class, new()`, base type, interface...) được **kiểm tra trước khi
  đóng**; candidate không thỏa sẽ bị bỏ qua.
- `ObjectFactory` được **cache theo cặp (request, response)**, nên chỉ phản chiếu (reflection) một lần.
- Chỉ kích hoạt khi có open-generic handler trong assembly; đường xử lý thường không tốn thêm chi phí.

## Điểm tối ưu trong thiết kế

- **Đăng ký exception behavior có điều kiện:** hai behavior xử lý ngoại lệ chỉ được thêm vào pipeline
  khi assembly thực sự có `IRequestExceptionHandler`/`IRequestExceptionAction`. App không dùng vẫn giữ
  nguyên fast-path zero-overhead (thay vì luôn thêm cho mọi request).
- **Covariant dispatch độc lập container:** không phụ thuộc container hỗ trợ variance.
- **Đóng generic handler theo arity bất kỳ:** hỗ trợ `Handler<T> : IRequestHandler<Query<T>, Box<T>>`
  (arity 1 vs 2) — điều MS.DI không đóng được.
- **Không reflection nóng:** cây type exception, invoker, và `ObjectFactory` của generic handler đều
  được cache.

## Thay đổi API

- `RequestHandlerDelegate<TResponse>` thêm tham số `CancellationToken` (mặc định — tương thích ngược).
- Mới: `IRequestExceptionHandler<TRequest, TResponse, TException>`,
  `IRequestExceptionAction<TRequest, TException>`, `RequestExceptionHandlerState<TResponse>`, `Unit`.
- `IRequest` nay kế thừa `IRequest<Unit>`; `IRequestHandler<TRequest>` kế thừa
  `IRequestHandler<TRequest, Unit>` (bắc cầu qua default interface implementation).

## Ghi chú nâng cấp

Đa số codebase không cần đổi gì. Một vài lưu ý:

- Nếu bạn từng ràng buộc generic trên đúng `IRequest` (không phải `IRequest<Unit>`), hãy kiểm tra lại —
  hầu hết trường hợp vẫn tương thích do `IRequest : IRequest<Unit>`.
- Khuyến nghị (không bắt buộc): cập nhật behavior để chuyển tiếp token `next(cancellationToken)`.
