# Release `v1.0.1`

## Tổng quan

Phiên bản `1.0.1` là bản vá (patch) cho `1.0.0`, tập trung vào **sửa lỗi và dọn dẹp chất lượng**,
**không thay đổi/không phá vỡ API** hiện có. Các tính năng mới (cancellation xuyên pipeline, covariant
notification, exception handlers/actions, constrained generic handlers) nằm ở `v1.1.0`.

Vẫn hỗ trợ `net7.0`, `net8.0`, `net9.0`. Giữ giấy phép MIT.

## Sửa lỗi

### Command void (`IRequest`) nay đi qua pipeline behavior

Trước `1.0.1`, request không có response (`IRequest`) được xử lý bằng một đường riêng, **bỏ qua toàn
bộ `IPipelineBehavior`** — nghĩa là logging, validation, và các behavior cross-cutting khác **không
áp dụng** cho command void.

Từ `1.0.1`, `IRequest` được mô hình hóa là `IRequest<Unit>` nên command void chạy qua **cùng một
đường pipeline** với request có response. Các behavior cross-cutting giờ áp dụng nhất quán cho cả hai.

> Với người dùng: không cần đổi code. Handler khai báo `IRequestHandler<TCommand>` với `Task Handle(...)`
> và command `IRequest` vẫn hoạt động như cũ, chỉ khác là nay được đi qua pipeline.

## Cải thiện chất lượng

### Build sạch, không còn cảnh báo

- Bổ sung tài liệu XML (`///`) cho toàn bộ thành viên public còn thiếu → hết cảnh báo `CS1591`.
- Khớp phiên bản package `Microsoft.Extensions.DependencyInjection.Abstractions` theo từng target
  framework (`7.0` cho net7.0, `8.0.2` cho net8.0, `9.0.0` cho net9.0) → hết cảnh báo tương thích
  TFM đối với `net7.0`.

Kết quả: build `0 Warning(s), 0 Error(s)` trên cả ba target framework.

## Tương thích

- **Không phá vỡ API:** mọi request/command/handler viết cho `1.0.0` tiếp tục biên dịch và chạy nguyên vẹn.
- Bổ sung kiểu `Unit` biểu diễn "không có giá trị"; hầu hết trường hợp không cần dùng trực tiếp.

## Ghi chú

Bản vá này chuẩn hóa hành vi pipeline cho command void và làm sạch cảnh báo build, tạo nền tảng ổn
định trước khi bổ sung các tính năng nâng cao ở `v1.1.0`.
